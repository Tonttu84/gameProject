# Decisions

Workflow and tooling decisions for this project. The game's design decisions live in
`docs/CAMPAIGN_PLAN.md` under their own ids (M-*, S*-*, C-*, E-*, SB-*). One row per decision.
Never rewrite an old row: a reversal is a new row that names the one it replaces.

| ID | Decision | Reason | Chosen against |
| --- | --- | --- | --- |
| D1 | The project moves onto the owner's shared ai-workflow rules as a **solo** project (owner's choice, 2026-11-10). `AGENTS.md` is the rulebook, `CLAUDE.md` is the one line `@AGENTS.md`, and the history behind the old `CLAUDE.md` rules moved to `docs/history.md`. Rules the shared agreements now cover (grilling, the coordinator and subagent split, branch checks, shipping) were dropped from the project file. | One way of working across the owner's projects; `AGENTS.md` is the format other coding tools read. | Keeping the long `CLAUDE.md` as the project rulebook. |
| D2 | The project keeps one step on top of the shared solo flow: after the push, watch CI on the pushed commit until it is green. Agent's choice, keeping the project's 2026-08-10 shipping rule. | The sanitized engine suite, the Docker smoke and the end-to-end tests run only in CI, so the local gate cannot catch what they catch. | Treating the local gate as the whole check. |
| D3 | Two decision records: this file for workflow and tooling, `docs/CAMPAIGN_PLAN.md` for game design. Agent's choice. | The campaign plan already holds hundreds of cited design decisions under its own ids; moving them would break every citation in code comments and docs. | Moving the design decisions here. |
| D4 | The commit hooks from ai-workflow's `hooks/install.sh` in its default mode: committed in `.githooks/`, turned on by `core.hooksPath`. `make setup` sets it, natively on Windows without WSL; the Claude `SessionStart` hook sets it on every session; `.gitattributes` keeps `.githooks/*` at LF. Agent's choice. | `.git/hooks` held only samples, so nothing was switched off. The Makefile forwards every other goal to WSL, which a git config line does not need. Hooks without an extension fell outside the existing `*.sh eol=lf` rule, and a CRLF shebang breaks them. | `--git-hooks` (copies into `.git/hooks` that a clone never gets); a separate setup script. |
| D5 | The vendored `grill-me` and `grilling` skills, `scripts/check_claude_skills.sh`, its `claude-skills` CI job and the `.gitignore` exceptions that let `.claude/skills/` through are removed. Owner's choice (ai-workflow D22, 2026-11-10). | The skill is installed once at user level from ai-workflow; per-project copies diverged by timing. With no vendored skills, the check that they survive a clone has nothing to check. | Keeping the copies; keeping the job pointed at an empty folder. |
| D6 | `.github/workflows/commit-check.yml` from ai-workflow's template, unchanged: every commit of a push to `main` and of a pull request, plus the PR title, checked with the committed `.githooks/commit-msg`. It keeps the push and pull-request triggers. Agent's choice under ai-workflow D36 and D39. | The repository is public, so Actions minutes on standard runners cost nothing; the local hooks are only feedback. | The private-repo variant (pull requests, manual and weekly runs only). |
| D7 | Dependabot version updates from ai-workflow's template on the 1st and 15th: `github-actions`, and `npm` for `/campaign-server`, `/frontend` and `/e2e` in one grouped pull request (`directories`). Security updates and vulnerability alerts are on in the repository settings. Agent's choice under ai-workflow D37. | The three Node packages share the toolchain and are tested together; one grouped update keeps the lockfiles in step. The workflows' actions are tag-pinned today; Dependabot moves them. | One npm entry per directory (three pull requests per run); leaving out the Dockerfile's base images, which the template does not cover (listed as a gap). |
| D8 | Function limits as warnings (ai-workflow D42), set from Lizard on 2026-11-10 over the production code (tests and bundled `extern/`, `catch.hpp` left out). **C++** (593 functions; `.clang-tidy`): cognitive complexity 20, 80 lines, 5 parameters, nesting 4. Lizard flags 17 functions over cyclomatic 20 (2.9%; 34 or 5.7% over 15), 15 over 80 lines (2.5%; 29 or 4.9% over 60), 7 over 5 parameters (1.2%). **Front end** (oxlint in `frontend/.oxlintrc.json`): the starting values, complexity 15, 60 lines (blank lines and comments skipped), 5 parameters, depth 3, with the line limit off in `src/__tests__/`. oxlint flags 16 functions over complexity 15 and 32 over 60 lines, of about 976 front-end functions (Lizard's count), and none over the parameter or depth limits. Agent's choice. | The template's starting values already flag only a few percent of the front end, but about 5% of the engine, so the C++ complexity and length limits sit one step higher. Test files are long `describe` callbacks by design. clang-tidy's cognitive measure was not run (no clang-tidy on the machine), so its 20 rests on Lizard's cyclomatic numbers; revisit after a first clang-tidy run. | The starting values for C++ too; no line-limit exception for tests; a linter for `campaign-server/`, which has none (listed as a gap). |
